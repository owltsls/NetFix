## 三、找到的问题（按证据强度排序）

### 🔴 问题 1（直接根因）：系统代理指向死端口，且代理软件不在

| 检查项 | 值 | 判读 |
| --- | --- | --- |
| `HKCU\...\Internet Settings\ProxyEnable` | **1（已启用）** | 系统代理开关被打开了 |
| `ProxyServer` | **127.0.0.1:7897** | 7897 是 Clash / Mihomo 系代理软件的经典混合端口 |
| 7897 端口监听 | **空**（`Get-NetTCPConnection` 无任何结果） | ❌ 没有任何程序在监听 |
| 代理类进程 | **空**（无 Clash/V2Ray/Verge 等进程） | ❌ 代理软件没有运行 |
| WinHTTP 代理 | **直接访问（没有代理服务器）** | 与 WinINET 不一致 → 两套网络栈走向不同 |
| 自启动项 | 无代理软件 | 代理软件不是"没启动"，而是"不在了/被关了" |
| 卸载列表 | 无代理软件安装记录 | 说明配置是**残留**下来的（软件已卸/曾临时用过） |

**结论**：Edge 等走 WinINET 的程序，请求被强制发往 `127.0.0.1:7897`，但该端口无人应答 → 浏览器"连不上网"；走 WinHTTP / 直连 / 自带网络栈的软件（如部分桌面程序、系统服务）不受这段配置影响 → 照常上网。

### 🟡 问题 2（次生隐患）：环境变量代理残留，可能拖垮命令行工具

| 变量 | 值 |
| --- | --- |
| HTTP_PROXY / HTTPS_PROXY | `http://127.0.0.1:4612` |
| HTTP_PROXY / HTTPS_PROXY（小写） | `http://127.0.0.1:4612` |
| NO_PROXY | `127.0.0.1,localhost,::1` |

> 4612 由 WorkBuddy 沙箱进程占用，**属于本次诊断环境**。但它说明一件事：这台机器上"代理配置残留"不是一个孤例——注册表、环境变量、虚拟网卡三处都留下了代理相关配置，只是来源不同。若用户曾手动配过环境变量代理，git / npm / pip / curl 等工具也会受影响。

### 🟡 问题 3（可疑残留）：虚拟网卡 DNS 指向本机

- 网卡 `本地连接* 10`（Microsoft Wi-Fi Direct Virtual Adapter #2）DNS = `127.0.0.1`，状态 Disconnected。
- 本身未连接、不影响当前上网，但 `127.0.0.1` 作为 DNS 通常是代理软件 TUN 模式或 DNS 劫持工具的残留写法，建议纳入修复工具的检查项。

## 四、回答你的四个问题

### Q1：什么软件什么问题？
**没有"软件本身坏了"**。Edge 正常安装、系统正常、hosts 干净、网卡正常。问题出在**系统级配置残留**：代理开关被打开、指向一个已经不存在的代理程序。真正"有问题"的是一个配置，不是一个软件。

### Q2：浏览器为什么没法访问网络？
因为浏览器（Edge）默认走 Windows 的 **WinINET** 代理设置。这里的代理被设成了 `127.0.0.1:7897`，而该端口无人监听。浏览器把每一个网页请求都先交给这个"死代理"，自然全部失败。

### Q3：能不能多种因素导致"浏览器不能上网，但其他软件能"？
**能，而且很常见。** Windows 有多套互相独立的网络栈：

| 网络栈 / 通道 | 谁在用 | 本机当前状态 |
| --- | --- | --- |
| WinINET（注册表 Internet Settings） | Edge/IE、多数桌面软件 | ❌ 代理=127.0.0.1:7897（死端口） |
| WinHTTP | Windows 更新、部分服务、PowerShell | ✅ 直连，不受影响 |
| 环境变量代理 | git / npm / pip / curl 等命令行 | ⚠️ 残留 4612（沙箱注入） |
| 软件自带 socket / 直连 | 微信、QQ、Steam、下载器等 | ✅ 完全不看系统代理 |
| 浏览器扩展代理 | SwitchyOmega 等 | 未安装，排除 |
| hosts / DNS / 防火墙 / TUN 虚拟网卡 | 各类 | hosts 干净；虚拟网卡有可疑残留 |

所以只要故障落在其中**某一条通道**上，就会出现"这家软件断网、那家软件正常"的诡异现象。

### Q4：为什么第一次遇到？
因为这是**配置残留**，不是系统损坏。常见触发方式：
1. 曾用过一次代理/VPN/加速器（或同事帮你调过），软件退出或卸载时**没有还原系统代理开关**；
2. 某个"网络优化/一键加速"工具改过设置后没恢复；
3. Edge 某次更新后开始严格遵守系统代理设置（以前可能忽略）。

第一次遇到很正常——它只在"代理配置与代理软件不同步"时才会暴露。

## 五、眼下最快的解决办法（不改任何文件，手动即可）

1. `Win + R` → 输入 `inetcpl.cpl` → 回车 → 「连接」→「局域网设置」
2. **取消勾选**「为 LAN 使用代理服务器」→ 确定
3. 重启 Edge → 立即恢复

或用管理员 PowerShell 一条命令：

```powershell
Set-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyEnable -Value 0
```

> 本次诊断严格只读，**没有替你执行上述修改**。修复工具的"一键恢复网络初始状态"正是把这类操作标准化、可回滚、可审计。
